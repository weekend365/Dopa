# ADR-0003: 개발용 생활 안내와 별도 로컬 자기보고 기록

- 날짜: 2026-09-10
- 상태: 이번 사용자 지시 범위의 개발 구현 결정. 운영 출시 결정 아님.
- 관련: [전체 계획](../product/COMPANION_IMPLEMENTATION_PLAN_KO.md), [Scope v1.3](../product/MVP_SCOPE_FREEZE_V1_KO.md)

## 결정과 이유

Flutter/Riverpod/GoRouter/Drift를 유지한다. 실제 동행 미디어가 없으므로 무료 책상 텍스트 샘플 한 개를 dev flavor에만 노출한다. prod는 직접 경로도 거부한다.
제품명은 ‘같이 시작하기’ 하나를 사용하고 현재 제공되지 않는 콘텐츠/음성/결제를 표시하지 않는다.

안내를 넘겼다는 사실과 행동을 했다는 자기보고는 별개다. Drift v4에 `companion_runs`, `companion_outcomes`를 추가하고 원본 집중·체크인·성장 테이블은 수정하지 않는다.
안내 단계는 DB에 저장하고, 재생·자동넘김은 메모리에 둔다. 화면 이탈/비활성 시 정지, 복원 시 현재 단계 처음부터 사용자가 이어가도록 한다.
시계 변경/백그라운드 경과 시간으로 행동을 추정하지 않으며 초 단위 남은 대기시간 복원은 제공하지 않는다.

실행 생성은 활성 slot unique로 중복을 막고, 결과 입력은 run ID primary key와 트랜잭션으로 첫 확정만 반영한다. 결과 삽입과 활성 해제 중 한쪽이 실패하면 모두 롤백한다.
성장과 집중시간에는 연결하지 않는다. 기존 `sourceSessionId` FK에 생활 기록을 억지로 넣지 않고 후속 설계에서 별도 원인 모델을 검토한다.

## 개인정보·호환성

실행/결과는 동일 기기 계정 로컬 DB만 사용한다. 자유 입력/진단/메시지/사진/분석 전송/서버 serializer/새 권한·SDK가 없다.
기존 연령·로그인·동의 게이트 이후만 접근한다. 기존 로그아웃/계정 삭제 트랜잭션에 두 테이블을 포함한다. 개별 결과 삭제는 해당 실행도 cascade 삭제한다.
프로세스 중단 후 복원, v2/v3 원본 보존, 기존 집중/성장 동작 유지와 중복 결과를 테스트한다. schema v1 회귀 검사도 유지한다.
샘플은 content ID/version으로 식별하고 제작본은 새 버전으로 등록하여 과거 샘플을 사람 콘텐츠 사용 근거로 합산하지 않는다.

## 대안과 롤백

별도 파일/새 DB는 계정 삭제 누락·중복 상태 관리 위험 때문에 사용하지 않았다. 가짜 미디어 URL, TTS를 실제 출연 콘텐츠로 표기, 구매 성공 대역은 추가하지 않았다.
중단은 벌점이나 나무 차감이 아니다. 결과 대기 단계도 복원하며 사용자 선택 없이 실패/성공을 저장하지 않는다.
샘플 롤백은 노출 provider를 false로 변경하되 v4 테이블/마이그레이션은 유지한다. 이미 v4로 연 DB를 v3 코드로 열거나 사용자의 DB를 삭제해서 복구하지 않는다.
앱 및 데이터 삭제/마이그레이션을 실제 iOS·Android에서 재확인하고, 원본 제작/권리 확보와 출시 승인 이전에는 운영 노출을 활성화하지 않는다.
