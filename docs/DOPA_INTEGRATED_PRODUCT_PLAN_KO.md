# 1. 한 페이지 사업 개요

## 해결하려는 문제

숏폼, SNS, 게임, 커뮤니티는 사용자가 의도하지 않았는데도 습관적으로 열기 쉽다. 문제는 스마트폰 사용시간 그 자체가 아니라 다음과 같은 `의도와 실제 행동의 불일치`다.

- 잠깐 확인하려다 30분 이상 머문다.
- 집중하거나 쉬고 싶은 시간에도 같은 앱을 반복해서 연다.
- 사용 기록을 보고 후회하지만 다음 행동을 바꾸는 방법은 찾지 못한다.
- 강한 차단 앱은 답답해서 해제하고, 스트릭이나 경고는 수치심을 만든다.

Dopa는 사용자를 평가하지 않고 `관찰 → 선택한 경계 → 짧은 보호 → 오프라인 대안 → 회고 → 개입 축소`의 행동 루프를 제공한다. 디지털 자기통제 도구는 단기 사용 감소에 유망하지만 장기 효과와 수면·정신건강 개선 근거는 제한적이므로, Dopa는 치료나 효과 보장이 아닌 자기조절 지원 도구로 포지셔닝한다. [디지털 자기통제 도구 메타분석](https://doi.org/10.1145/3571810), [조건부 개입 RCT](https://mhealth.jmir.org/2026/1/e56824/)

## 목표 사용자

- 핵심: 숏폼, SNS, 게임, 커뮤니티 사용을 줄이고 싶은 18~39세
- 이용 가능: 만 14세 이상. 14~17세 정책·동의·스토어 분류는 출시 전 전문 검토
- 주요 상황: 출퇴근 숏폼, 공부·업무 중 반복 확인, 취침 전 영상·커뮤니티, 게임 세션 연장
- 공통 특성: 사용을 완전히 끊기보다 `내가 정한 시간과 상황에서는 덜 쓰고 싶은` 사람

## 핵심 가치 제안

1. **필요한 순간에만 개입한다.** 상시 감시 대신 사용자가 고른 1~3개 앱을 집중 세션 동안 보호한다.
2. **강제보다 자율성을 지킨다.** 우회와 중단은 언제나 가능하며, 이유 설명을 강요하지 않는다.
3. **기록에서 행동으로 연결한다.** 사용 패턴 뒤에 바로 7일 실험과 2분 오프라인 행동을 제안한다.
4. **민감한 기록을 기기 안에 둔다.** 앱명, 사용 기록, 체크인과 감정 맥락은 기본적으로 서버로 보내지 않는다.
5. **사용자가 Dopa에서도 졸업하게 한다.** 계획이 안정되면 알림과 개입을 줄인다.

## 대표 사용 시나리오

> 직장인 민지는 취침 전 숏폼 때문에 자는 시간이 늦어지는 상황을 바꾸고 싶다. Dopa에서 동영상·SNS 앱 2개와 밤 11시부터 30분 동안의 `화면 밖 준비` 계획을 고른다. 보호 시간이 되면 앱이 잠시 가려지지만, 필요한 사용이면 두 번 이내의 동작으로 우회할 수 있다. 대신 2분 스트레칭이나 종이 메모를 선택한다. 7일 후 Dopa는 “7일 중 4일에 계획을 시도했고 95분을 화면 밖에서 보냈어요”라고 보여주고, 개입을 유지·완화·중단할지 묻는다.

Dopa의 방어력은 단일 차단 기술이 아니라 한국 생활 맥락에 맞춘 프로그램, 플랫폼 차이의 정직한 설명, 최소 수집, 비난 없는 회고, 개입을 스스로 낮추는 졸업 경험에서 만든다.

## 엘리베이터 피치

> Dopa는 무의식적인 앱 열기를 7일의 작은 실험과 선택형 집중 보호로 바꿔, 사용자가 휴대폰이 아니라 자신의 의도대로 시간을 쓰도록 돕는 한국형 디지털 웰빙 앱이다.

## 브랜드 슬로건 5개

1. 덜 열고, 더 살아가기
2. 멈춤은 벌이 아니라 선택
3. 화면 밖의 시간을 되찾다
4. 내 의도대로 쓰는 스마트폰
5. 조용히, 다시 나에게

## 핵심 페르소나 3개

## Jobs To Be Done

- 집중하려는 순간, 방해 앱을 완전히 포기하지 않고도 일정 시간 접근을 어렵게 만들고 싶다.
- 무의식적으로 앱을 열었을 때, 수치심 대신 원래 하려던 일을 다시 선택할 작은 틈이 필요하다.
- 일주일이 지난 뒤 단순 사용시간이 아니라 `내가 정한 경계를 얼마나 지켰는지` 알고 싶다.
- 필요한 연락·교통·금융·인증은 막지 않으면서도 나머지 앱에는 경계를 만들고 싶다.
- 기록을 회사 서버에 쌓지 않고 내 기기 안에서 스스로 패턴을 이해하고 싶다.

## 사용자 여정

| 단계 | 사용자 생각 | Dopa 경험 | 핵심 지표 |
|---|---|---|---|
| 발견 | “앱을 덜 쓰고 싶지만 또 실패할까?” | 치료·의지력 표현 없이 7일 작은 실험을 제안 | 스토어→설치 전환 |
| 첫 실행 | “왜 이런 권한이 필요하지?” | 연령 확인→로그인→목표 상황→권한의 용도·로컬 처리 설명 | 로그인·권한 완료율 |
| 첫 성공 | “짧게라도 방해 없이 해보자” | 5~10분 집중 세션과 선택 앱 보호 | 첫 세션 시작·완료율 |
| 첫날 | “언제, 무엇을 바꿀까?” | 목표 앱 1~3개, 시간대, 오프라인 대안 선택 | 계획 생성률 |
| 7일 실험 | “계획대로 안 된 날도 있다” | 스트릭 대신 시도 수, 우회 가능, 선택적 체크인 | 3일 이상 시도율 |
| 주간 회고 | “무엇이 실제로 도움이 됐지?” | 의도 일치·보호 시간·데이터 누락을 구분해 표시 | 리포트 조회·계획 조정률 |
| 안정·졸업 | “이제 덜 개입해도 되겠다” | 알림·차단 강도 낮추기 또는 계획 종료 | 개입 축소 후 유지율 |

## 해결해야 할 문제

- 무의식적 반복 열기와 사용 연장
- 집중·취침 등 사용자가 보호하고 싶은 생활 장면
- 사용 기록과 실제 행동 변화의 단절
- 차단 실패·권한 철회·플랫폼 차이에 대한 불신
- 실패를 의지 부족으로 느끼게 만드는 UX

## 해결하지 않을 문제

- 인터넷·게임·SNS 중독의 진단 또는 치료
- ADHD, 우울, 불안, 불면 등 정신·의학적 상태의 진단
- 자녀·직원 감시 또는 강제 기기 관리
- 모든 기기와 웹사이트의 완전 차단 보장
- 생산성 점수로 사람을 평가하거나 타인과 순위를 매기는 기능

# 3. 제품 원칙

| 원칙 | 제품 결정 기준 |
|---|---|
| 1. 관찰하되 비난하지 않는다 | 사람 대신 행동을 설명한다. `실패·중독·의지 부족·망쳤다`를 금지한다. |
| 2. 사용자가 경계를 정한다 | 대상 앱, 시간, 강도, 대안을 사용자가 고른다. 기본값은 제안이지 강제가 아니다. |
| 3. 언제든 안전하게 바꿀 수 있다 | 중단·우회·권한 철회가 가능하며 우회 이유 입력을 강제하지 않는다. |
| 4. 알림은 약속한 순간에만 보낸다 | 첫 실행에 권한을 묻지 않는다. 예약 루틴과 주간 리포트 외 재참여 알림은 기본 OFF다. 하루 최대 2회다. |
| 5. 데이터는 가능한 기기 안에 둔다 | 앱명·사용량·감정 맥락은 로컬이 기본이다. 수집 여부보다 제품에서 실제로 보내지 않는 구조를 우선한다. |
| 6. 의학적 효과를 과장하지 않는다 | 사용 감소·수면·집중·정신건강 개선을 보장하지 않고 근거의 표본·기간·한계를 함께 쓴다. |
| 7. 누구나 읽고 조작할 수 있어야 한다 | WCAG 2.2 AA, VoiceOver·TalkBack, 200% 글자 확대, 충분한 터치 영역을 출시 조건으로 둔다. |
| 8. 플랫폼 한계를 숨기지 않는다 | `측정 가능 / 부드러운 보호 / 타이머만` 상태를 기기별로 보여준다. |
| 9. Dopa 의존을 줄인다 | 계획이 안정되면 알림과 개입을 낮추고, 앱 미실행을 이탈이 아닌 졸업 신호로도 해석한다. |

## 플랫폼별 실제 구현 범위

### iOS

- 최소 지원 iOS 16. 제출 시점의 최신 Xcode·SDK 요건을 따른다. 2026-04-28 이후 제출은 iOS 26 SDK 이상 빌드가 필요하다. [Apple 제출 요건](https://developer.apple.com/app-store/submitting/)
- `FamilyActivityPicker`로 앱·카테고리·웹사이트를 선택하며 Dopa에는 실제 식별자가 아닌 opaque token이 전달된다.
- `ManagedSettingsStore`와 Shield Configuration/Action 확장으로 집중 세션 중 선택 앱을 가린다.
- Shield에서 복잡한 질문을 직접 받지 않고 `Dopa 열기 → 필요한 사용인지 선택 → 제한적으로 해제` 흐름을 사용한다.
- `DeviceActivityReportExtension`에서 SwiftUI 리포트를 렌더링한다. 대한민국에서 raw 앱별 데이터를 Flutter 계층·서버·분석 SDK로 옮기지 않는다.
- App, DeviceActivityMonitor, DeviceActivityReport, ShieldConfiguration, ShieldAction에 필요한 Bundle ID와 App Group을 1주 차에 만들고 Family Controls 배포 entitlement를 신청한다. 승인 SLA는 공개되지 않았다.

### Android

- 최소 Android 10(API 29), `targetSdk 36`으로 개발한다. 2026-08-31부터 신규 앱은 Android 16/API 36 이상 타깃이 필요하다. [Google Play API 요건](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)
- `PACKAGE_USAGE_STATS`는 일반 런타임 권한이 아니므로 설정 화면 이동 전 prominent explainer를 보여주고 복귀 시 실제 상태를 다시 검사한다.
- UsageStats 상세 이벤트 보관이 제한되므로 하루 한 번 로컬 일별 집계를 만들며, 권한 해제·잠금 상태로 생긴 공백은 `데이터 없음`으로 저장한다.
- 일반 소비자 앱용 공식 차단 API는 없다. AccessibilityService는 `isAccessibilityTool=false`, 집중 세션이 활성화된 동안 선택한 패키지로 전환됐는지만 확인하는 결정론적 범위로 제한한다.
- 화면 텍스트·알림·입력 내용을 읽지 않고, 자동 의사결정이나 삭제 방지를 하지 않는다. Play Console 선언·사전 고지·명시적 동의·심사 비디오를 준비한다.
- Accessibility가 거절되거나 꺼지면 `timerOnly`로 즉시 열화한다. 해당 기능은 Remote Config로 서버 배포 없이 끌 수 있어야 한다.

# 5. MVP 정의

## 12주 MVP 필수 기능

1. SDK 네트워크 초기화 전 연령 확인
2. Apple·Google 필수 로그인과 동의 버전 기록
3. 플랫폼 권한 설명·허용·거부·복구
4. 사용 패턴 리포트와 데이터 가용 상태
5. 방해 앱 1~3개 선택
6. 집중 세션과 세션 중 보호
7. 긴급 allowlist·우회·정상 열화
8. 7일 실험과 2분 오프라인 대안
9. 하루 1회 선택형 체크인
10. 기본 취침 전 디지털 휴식 템플릿
11. 주간 로컬 리포트와 계획 유지·완화·중단
12. 무료·유료 권한, 7일 체험, 구매 복원
13. 구독 관리 링크, 계정·로컬 데이터 삭제
14. 최소 분석·오류 추적·원격 기능 플래그

## 과감하게 제외할 기능

## 주요 흐름

### 온보딩

`약속 → 연령 계산 → 로그인 → 목표 상황 → 권한 explainer → OS 권한 → 앱 선택 → 첫 집중`

- 알림 권한은 첫 반복 일정을 저장한 직후에만 요청한다.
- 권한을 거부해도 수동 타이머와 체크인은 사용할 수 있다.
- 로그인 전 분석·Crashlytics·Remote Config 네트워크 초기화는 하지 않는다.

### 집중 세션

`시간 선택 → 대상 앱 확인 → 보호 강도 → 시작 → Dopa 자동 최소화 안내 → 완료/우회 → 1탭 회고`

- 활성 세션에서는 남은 시간만 크게 보여주고 앱 안 콘텐츠를 추가로 탐색시키지 않는다.
- 중단은 숨기지 않는다. “필요한 사용”과 “세션 끝내기”를 제공한다.

### 7일 실험

`바꾸고 싶은 장면 → 대상 → 시간 → 2분 대안 → 강도 → 7일 시도 → 주간 회고`

- 연속 기록 대신 `7일 중 시도한 날`을 표시한다.
- 하루를 건너뛰어도 진행률과 과거 성취는 사라지지 않는다.

### 주간 리포트

`데이터 가용성 → 시도한 날 → 보호한 시간 → 의도 일치 → 도움이 된 상황 → 유지/완화/종료`

- iOS 앱별 사용 차트는 native report 영역임을 디자인상 구분한다.
- 데이터가 불완전하면 변화율을 계산하지 않는다.

## 상태 설계

| 상태 | 표현 | 다음 행동 |
|---|---|---|
| 빈 상태 | “아직 비교할 기록이 없어요. 5분 세션부터 시작할 수 있어요.” | 빠른 집중 |

## 타이포그래피·간격·그리드

- Pretendard Variable을 우선하고 Apple SD Gothic Neo, Noto Sans KR, 시스템 sans-serif 순으로 폴백한다.
- 본문 기본 16sp, 보조 14sp, 제목 24/20sp, 타이머 48sp. 글자 확대 200%에서 잘리지 않아야 한다.
- 4pt 기반 간격 토큰: `4, 8, 12, 16, 24, 32, 48`.
- 모바일 좌우 기본 여백 20, 최대 콘텐츠 폭 600, 카드 간격 12.
- 고정 높이 텍스트 컨테이너를 피하고 화면 회전·큰 글자에서 스크롤을 허용한다.

## 컴포넌트 기본 규칙

- **버튼:** 한 화면의 primary action은 하나. 위험 행동은 구체적인 동사로 쓰며 계정 삭제 외에는 빨간 버튼을 쓰지 않는다.
- **카드:** 그림자보다 1px 경계와 명도 차를 사용한다. 카드 전체 탭 영역과 접근성 레이블을 제공한다.
- **입력:** 레이블을 placeholder로 대체하지 않는다. 생년월일은 기기에서 계산 후 즉시 폐기한다.
- **차트:** 색상 외에 값·패턴·레이블을 제공한다. 0과 데이터 없음, 목표와 평균을 구분한다.
- **모션:** 150~300ms, Reduce Motion에서 제거. 축하 폭발·랜덤 보상 애니메이션은 사용하지 않는다.

## 성취 시각화

- 잔잔한 파문이 넓어짐, 여백이 열림, 낮은 채도의 면이 채워지는 방식
- `연속 7일`보다 `7일 중 4번 시도`, `보호한 95분`, `개입 강도를 낮춤`을 강조
- 실패 시 성취 그래픽을 죽이거나 깨뜨리지 않음

## 앱 아이콘 콘셉트

1. **숨 고르는 D:** D자의 세로획 중간에 작은 틈을 둬 멈춤과 여백 표현
2. **열린 창:** 둥근 사각형 안에 화면 밖 빛이 들어오는 창을 표현
3. **잔잔한 파문:** 하나의 점에서 두 개의 부드러운 원이 퍼지는 형태

신경세포, 뇌, 번개, 주사기, 금지 표시는 의학적·공포적 인상을 줄 수 있어 제외한다.

## 핵심 API

| 메서드·경로 | 목적 | 저장 데이터 |
|---|---|---|
| `POST /v1/consents` | 동의 버전 기록·철회 | consent type/version/time |
| `GET /v1/content/challenges` | 승인된 실험·활동 템플릿 | 콘텐츠만 |
| `GET /v1/entitlements` | 유료 권한 확인 | entitlement |
| `POST /v1/analytics/batch` | App Check와 회전형 install ID로 allowlist 이벤트 전송 | Firebase UID 없이 검사 후 집계 |
| `POST /v1/webhooks/revenuecat` | 결제 상태 동기화 | uid, product, status |
| `DELETE /v1/account` | 삭제 작업 시작 | deletion job |

계정·동의·결제·삭제 API는 Firebase ID token을 사용한다. 분석 endpoint는 계정과의 결합을 피하기 위해 Firebase UID를 받지 않고 App Check, 회전형 install ID, rate limit을 사용한다. 공통으로 `/v1`, UTC ISO 8601, idempotency key, 명시적 error code를 적용한다. 원격 민감 데이터 동기화 API는 MVP에서 만들지 않는다.

## 오프라인 우선

1. 집중·챌린지·체크인은 항상 로컬에서 즉시 완료한다.
2. 서버가 없어도 기존 entitlement grace period 안에서 핵심 기능을 유지한다.
3. 동의·분석·오류 이벤트만 outbox에 쌓고 네트워크 복구 시 지수 백오프로 전송한다.
4. 분석 outbox는 7일 뒤 폐기한다. 앱명 등 금지 필드가 들어오면 전송하지 않고 개발 빌드에서 실패시킨다.
5. 서버 시간은 결제·동의에만 사용하고, 세션은 monotonic clock과 로컬 wall clock을 함께 사용해 시간 변경을 감지한다.

## 플랫폼 네이티브 연동 지점

- `UsageInsightsAdapter`: iOS `nativeView`, Android `structured`, 권한 없으면 `none`
- `FocusProtectionAdapter`: iOS `shield`, Android `accessibility` 또는 `timerOnly`
- `PermissionAdapter`: 설명 화면과 OS 설정 이동·상태 재확인
- iOS App Group 공유 저장소, Monitor/Report/Shield 확장 생명주기
- Android foreground notification, reboot/timezone receiver, OEM 진단, accessibility state

| 10,000 | 월 ₩15만~70만 | Functions 호출, Firestore, Crashlytics, RevenueCat 요금제 |

비용 상한은 Remote Config로 이벤트 샘플링과 비필수 분석을 끌 수 있게 한다. MAU 10만 이전에는 Kubernetes나 상시 서버를 도입하지 않는다.

## AI 코치 장기 구조와 안전장치


- 모델이 Accessibility 동작이나 차단 강도를 자동 결정하지 않는다.

## 계정 삭제 흐름

`설정 → 개인정보와 계정 → 계정 삭제 → 구독은 별도임을 설명하고 관리 링크 제공 → 최근 인증 → 로컬 즉시 삭제 → 서버 삭제 작업 → 완료 알림`

## 암호화 원칙

- 전송 TLS 1.2 이상, 서버 저장 제공자 암호화, 민감 로컬 필드 AES-GCM
- 암호화 키는 iOS Keychain·Android Keystore에 저장하고 로그·백업·분석에서 제외
- 앱 삭제·계정 삭제 시 키를 먼저 지워 복구 불가능하게 함
- 시크릿은 CI secret store와 서버 환경 변수에만 두며 모바일 번들에는 공개 가능한 키만 포함

## 분석 익명화·민감 행동 처리

- Firebase UID와 분리된 무작위 analytics ID 사용, 분석가용 테이블에 연결키 미제공
- 분석 endpoint의 요청 로그에서 IP와 인증 헤더를 제외하고 원본 HTTP 로그 보관을 최소화
- autocapture, session replay, 광고 ID, 화면 텍스트 수집 금지
- 정확한 시간 대신 필요한 경우 시간대 bucket, 기간은 bucket으로 전송
- 이벤트 allowlist를 클라이언트와 서버 양쪽에서 검증
- 앱명, package ID, iOS token, URL, 체크인 자유 입력은 스키마 차원에서 거부

## 반드시 지킬 규칙

- API는 `/v1`, UTC, idempotency, 인증, 명시적 error code, 속성 allowlist를 사용한다.
- Drift schema 변경에는 forward migration과 migration test가 필요하다.
- 전체 70%, domain/application 85% 커버리지 게이트를 통과한다. 생성 파일은 제외한다.
- 핵심 5화면은 golden·semantics test, 핵심 흐름은 실제 기기 E2E를 가진다.
- 최소 1명 승인과 CI 성공 전 병합하지 않는다.
- AI 도구에 운영 데이터·시크릿·사용자 로그를 입력하지 않는다.

## 창업자가 내려야 할 핵심 의사결정 5개

1. 14~17세 정책 비용을 감수할지, 전문 검토 결과에 따라 18세 이상으로 좁힐지

3. Android Accessibility 거절 시 강한 차단 없이도 포지셔닝을 유지할지
4. 필수 로그인의 이탈 비용을 감수할 만큼 계정이 초기 사업에 필요한지
5. 구독 가치를 ‘더 강한 차단’이 아니라 반복 루틴·리포트·프로그램에 둘지

## 최종 결론

Dopa의 가장 현실적인 첫 제품은 기능이 많은 디지털 웰빙 슈퍼앱이 아니다. `사용자가 바꾸고 싶은 한 장면과 앱 1~3개를 고르고, 필요한 시간에만 부드럽게 보호하며, 7일 뒤 비난 없이 조정하거나 졸업하는 제품`이다.

Flutter는 12주·2명 개발 조건에서 공통 UX를 가장 빠르게 만들 수 있지만 핵심 권한은 Swift와 Kotlin으로 직접 구현해야 한다. iOS raw 사용 데이터와 Android 차단 API의 차이를 숨기지 않고 capability 기반으로 설계해야 일정과 신뢰를 모두 지킬 수 있다. 데이터는 로컬에 두고 계정 서버를 최소화하며, 안전 우회와 기능 kill switch를 결제 기능보다 먼저 완성해야 한다.

수익화는 월 ₩5,900·연 ₩39,000의 무료+구독이 적합하다. 무료 사용자가 실제 7일 가치를 경험한 뒤 반복 계획과 장기 리포트에 과금하고, 광고·금전 벌칙·공포성 페이월은 사용하지 않는다. 장기 경쟁력은 가장 강한 차단이 아니라 한국 생활 맥락, 설명 가능한 플랫폼 동작, 검증 가능한 로컬 우선, 그리고 사용자가 Dopa 자체에서도 졸업할 수 있다는 신뢰에서 만들어야 한다.
